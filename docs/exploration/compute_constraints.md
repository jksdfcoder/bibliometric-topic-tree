## 对 Atlas 的实际决定

1. 湖机先做只读字段/引用/广字段档案提取与数据覆盖检查，当前有限分区pilot不代表全五年范围。
2. BM25在CPU建立基线；科学论文编码和多语言模型需要核查实际模型版本、许可、输入与部署。与现有推理并存时先小批测试峰值内存与吞吐，不凭“模型小”承诺6/8 GB一定足够。
3. 无独立标签与稳定错误模式之前，不训练LLM，不因双机可跑70B就选择70B。论文表示微调应优先评估适合表示任务的较小编码器，而非自动套用生成模型训练配方。
4. 基线效果确实要求微调时，先形成具体训练方案、数据隔离和收益标准，再安排worker资源；任何服务停止要明确服务影响与恢复方式，不在抽取脚本里隐藏执行。
5. 只有确有任务收益、单机无法容纳的已核实配方才考虑双机，并先检查分片加载和真实步时。无需现在规划70B/FSDP或解决超大MoE训练。
